# Корпоративная сборка Pi

Локальные изменения сделаны на основе Pi 1.0.2, commit `200387122ca450d6387f033949423114a270b96c`. Это отдельная сборка из исходников. Установленный `~/.local/bin/pi` не заменён. Поддерживаются Node.js на macOS с `/usr/bin/sandbox-exec` и Linux с непривилегированными namespaces, seccomp и `/usr/bin/bwrap`.

## Что разрешено

Модель получает полный разрешённый пользователем контекст, включая код, результаты инструментов, сжатые блоки ACP и задачи субагентов. Прогрев кеша сохранён. Кодирование, локальные сессии, экспорт, восстановление контекста и проверенные расширения работают внутри одного сетевого ограничения.

Адреса моделей задаются в `models.json`; отдельный `network-policy.json` разрешает конкретные схемы, имена серверов и порты. Настройка модели сама по себе не расширяет сетевые разрешения. Нет разрешения — нет запроса. Некорректная политика или ошибка запуска изоляции останавливает Pi.

## Настройка перед первым запуском

Новый профиль по умолчанию находится в `~/.pi-corporate/agent`. Старый профиль `.pi` автоматически не переносится. Переменная `PI_CODING_AGENT_DIR` может указать другой отдельный каталог. Проектные настройки этой сборки также используют `.pi-corporate`.

Создайте каталог с правами `0700`. Конфигурацию и ключи храните с правами `0600`. Не добавляйте их в Git. Пока Pi запущен, глобальные `network-policy.json`, `models.json`, `auth.json`, `settings.json`, код Pi и разрешённые расширения защищены от записи его инструментами. Изменяйте их после завершения процесса.

Пример `network-policy.json`:

```json
{
  "providers": {
    "corporate": {
      "modelOrigins": ["https://llm.company.example"],
      "authOrigins": []
    }
  },
  "extensions": []
}
```

Замените пример адресом своего сервера. В политике нужен origin без `/v1`, параметров, логина и пароля; порт входит в разрешение. Поддомены и другие порты не разрешаются автоматически. Для удалённых серверов требуется HTTPS. HTTP разрешён только для `localhost`, `127.0.0.1` и `::1`, например для локального тестового сервера. Эти имена проверяются отдельно.

Пример `models.json` для OpenAI-compatible Chat Completions:

```json
{
  "providers": {
    "corporate": {
      "baseUrl": "https://llm.company.example/v1",
      "api": "openai-completions",
      "apiKey": "$CORPORATE_LLM_API_KEY",
      "models": [{"id": "replace-with-real-model-id"}]
    }
  }
}
```

Укажите фактический ID модели и её `contextWindow`/`maxTokens`, если они отличаются от значений Pi по умолчанию. Ключ передайте локально через переменную окружения или предварительно подготовленный `auth.json`. Не присылайте его в чат. Настройка `$NAME` разрешается непосредственно при запросе. Сохранение ключа через `/login` в запущенной сборке не поддерживается из-за защиты `auth.json` от записи.

Поддержанные и проверенные синтетическими тестами API: `openai-completions`, `openai-responses`, `anthropic-messages`, `azure-openai-responses`. Остальные протоколы отклоняются до отправки модельного запроса. Для Azure задайте согласованный адрес в `models.json` и, если нужна, `AZURE_OPENAI_BASE_URL`; фактическое назначение запроса всё равно проверяется.

Пример `settings.json`:

```json
{
  "defaultProvider": "corporate",
  "defaultModel": "replace-with-real-model-id",
  "extensions": []
}
```

При корпоративном CA задайте `NODE_EXTRA_CA_CERTS` с доверенным PEM-файлом **до** запуска Node. Проверка сертификатов остаётся включённой. Настройки, требующие внешнего корпоративного HTTP-прокси, SSO или обновления OAuth-токенов, необходимо отдельно проверить и при необходимости реализовать; этот вариант рассчитан на прямое соединение брокера с моделью и заранее доступный API-ключ. `authOrigins` разрешает адреса в сетевой политике, но не реализует SSO.

## Подключение billion-context-pi

Соберите проверенную локальную версию плагина. В ней отключён обновлятор, а ACP и ядро упакованы в один файл. Для текущего рабочего каталога:

```sh
cd /Users/alexantonov/sources/billion-context-pi
npm run build
shasum -a 256 dist/index.js
```

Добавьте абсолютный путь в `settings.json` → `extensions`. В `network-policy.json` добавьте тот же файл и полученный хеш:

```json
"extensions": [
  {
    "path": "/Users/alexantonov/sources/billion-context-pi/dist/index.js",
    "sha256": "replace-with-64-lowercase-hex-characters"
  }
]
```

При изменении сборки прежний хеш не подходит: загрузка отклоняется до импорта. Хеш закрепляет входной файл, а не произвольное дерево зависимостей. Для других расширений проверяйте все зависимости и используйте самодостаточные сборки с доверенными импортами API хоста. Встроенные расширения Pi входят в доверенную сборку; сетевые запросы их инструментов подчиняются общему ограничению.

`acp_delegate` запускает закреплённый CLI этой сборки. Дочерний процесс наследует профиль, сетевой прокси и ограничения ОС. Он проверяет SHA-256 CLI и действительную изоляцию; отсутствующая модель роли приводит к ошибке. Переход на глобально установленный Pi отсутствует.

## Подготовка Linux

Для сборки нужны Node.js >=22.19, C-компилятор и заголовки libc/Linux. Для запуска нужен bubblewrap >=0.8 без setuid/setgid, установленный как `/usr/bin/bwrap`, а также разрешённые пользовательские namespaces и seccomp. Пример подготовки Debian/Ubuntu выполняется оператором вне Pi:

```sh
sudo apt-get update
sudo apt-get install --no-install-recommends bubblewrap build-essential
cd /absolute/path/to/pi
npm ci --ignore-scripts
npm run build:offline
```

`build:offline` предполагает уже подготовленные и проверенные JSON каталога моделей в `packages/ai/src/providers/data`. Они не входят в Git: возьмите их из проверенного пакета той же версии либо используйте штатную подготовку каталога вне рабочего запуска Pi. Проверка: `npm run check:model-data`. Подготовка зависимостей и каталога может обращаться к внешним серверам; она не должна выполняться с корпоративным контекстом или ключами.

Linux-сборка компилирует небольшой helper из `src/core/corporate-linux-helper.c` в `dist/corporate-linux-helper`; дополнительных npm-зависимостей нет. Собирайте его на целевой архитектуре и совместимой libc. Перенос macOS-сборки без Linux-helper не поддерживается. C-код рассчитан на ARM64 и x86-64; нативные интеграционные проверки выполнены на ARM64. Другие архитектуры отклоняются при сборке.

Если ОС, AppArmor или контейнерный профиль запрещают необходимые namespaces/монтирование `/proc`, запуск завершится ошибкой. Автоматического запуска без защиты, sudo или привилегированного helper нет. Такие ограничения нужно согласовать с администратором и проверить на целевой машине.

## Запуск сборки

Из каталога проекта:

```sh
node /Users/alexantonov/sources/pi/packages/coding-agent/dist/bundle/cli.js
```

Для одного ответа добавьте `-p "задача"`; для RPC — `--mode rpc`. Отдельно задавать `PI_TELEMETRY=0` или `--offline` не нужно: ограничения обязательны в этой сборке и не снимаются переменными окружения.

Для приложения SDK:

```sh
node /Users/alexantonov/sources/pi/scripts/corporate-sdk.mjs /absolute/path/to/app.mjs
```

Обычный `createAgentSession()` вне защищённого запуска отклоняется. Самостоятельное использование низкоуровневого `pi-ai`, сторонних процессов вне запуска или исходного установленного Pi не получает эту защиту автоматически.

## Как ограничена сеть

Родительский процесс создаёт закрытый от изменений снимок политики и локальный прокси. macOS разрешает Pi и всем его потомкам только TCP-соединения к этому прокси. Прокси проверяет назначения HTTP и CONNECT по разрешённым origin; он сам разрешает DNS-имена модели. Прямые TCP/UDP/DNS, сторонние прокси, Unix-сокеты и запуск браузера через системные IPC не разрешены. `curl`, Python, bash и расширения наследуют это ограничение, даже если игнорируют переменные прокси.

На Linux bubblewrap создаёт отдельные user/network/PID/mount/IPC/UTS namespaces, убирает capabilities и запрещает новые пользовательские namespaces. У процесса нет внешних интерфейсов и маршрутов. Доверенный мост передаёт TCP с собственного loopback-порта через приватный Unix-сокет родительскому прокси; DNS разрешает только родитель. Мост не исполняет команды из запросов и закрыт от изменения памяти через `/proc`.

Перед запуском Node helper обязательно включает `no_new_privs` и seccomp. Pi и его потомки не могут создавать именованные Unix-сокеты, UDP/raw/netlink-сокеты, использовать io_uring для обхода фильтра, менять namespaces/монтирования или обращаться к памяти других процессов. Фильтр наследуется при fork/exec. Перед работой CLI/SDK проверяет действительный seccomp, отсутствие capabilities/внешних маршрутов и отказ Unix-сокета; одной переменной окружения недостаточно. Вся файловая система смонтирована для чтения; запись разрешена только в рабочий каталог, профиль и приватный временный каталог, с отдельной защитой конфигурации и доверенного кода. `/proc` закрыт для записи, `/dev` создаётся заново, прежние `/tmp` и `/run` скрыты.

Readonly bind mounts защищают пути и запрещают создание новых hard-link обходов. Не готовьте существующие writable hard links на доверенные файлы внутри рабочего каталога; внешние процессы вне изоляции также могут менять исходные файлы. Для эксплуатации отделяйте установленный доверенный код от редактируемого проекта.

Анонимные уже соединённые Unix stream socketpairs разрешены для stdin/stdout дочерних процессов Node; они не дают подключения к именованному сокету хоста. Datagram/seqpacket socketpairs запрещены, чтобы исключить повторное подключение пары к внешнему IPC-сокету.

Для модельных запросов дополнительно проверяется привязка адреса к провайдеру: до получения ключа, после разрешения авторизации и перед фактическим fetch. Все HTTP-перенаправления модели отклоняются. OpenAI SDK может представить отказ как `Connection error` и повторить запрос к разрешённому исходному адресу.

Отключены установка телеметрии, проверки версии, удалённые каталоги, загрузка инструментов, автоустановка/обновление пакетов, публикация сессий/отчётов и экспериментальный удалённый режим. Редактирование кода сохранено, но команды, которым нужен сторонний сетевой сервис, например внешние `git fetch` или `npm install`, внутри Pi работать не будут. Зависимости проекта готовьте отдельно контролируемым процессом.

Прогрев кеша, сжатие и делегирование могут передавать полный контекст разрешённому модельному серверу. Эта политика не ограничивает обработку данных самим разрешённым сервером и не проверяет его внутренние маршруты или хранение запросов. Его нужно выбирать по корпоративным правилам.

## Локальные данные

Сессии и sidecar ACP сохраняются для восстановления исходных деталей. Результаты и сессии субагентов: `<agentDir>/corporate-state/acp-delegate`; диагностика ACP: `<agentDir>/corporate-state/acp.log`. Новые каталоги создаются с `0700`, файлы — с `0600`; диагностические поля ключей, Bearer-токенов и URL-параметров маскируются. Это не удаляет произвольные секреты из текста сессии или кода: локальные контекстные файлы сохраняют полный текст и требуют такого же контроля доступа, как рабочий репозиторий.

Временные файлы процесса остаются в отдельном приватном `pi-corporate-*` внутри системного временного каталога. Снимки политики — в `corporate-state/launch-*`. Проверяйте сроки локального хранения; удаляйте ненужные данные после завершения процесса. Старая установка, внешние синхронизаторы и процессы вне изоляции не контролируются этой сборкой.

HTML-экспорт содержит локальные библиотеки и CSP: внешние изображения, fetch, шрифты, фреймы и формы блокируются. Встроенные `data:`-картинки отображаются. Открытие пользователем обычной внешней ссылки является отдельной сетевой операцией браузера.

## Что проверено и что осталось

Сборка без загрузки каталога моделей, статическая проверка Pi, целевые тесты политик/транспортов/прогрева, весь набор тестов ACP. Реальные собранные CLI, RPC, SDK и `acp_delegate` проверены с локальной синтетической моделью. Нативное ограничение проверено для Node, `curl`, потомков и защищённых файлов. Интерактивный Pi получил ответ в отдельном PTY и завершился. HTML открыт в браузере: принимающий тестовый сервер получил ноль запросов картинки и fetch.

Linux проверен на Debian 12 ARM64, Node 22.19 и настоящем ядре Linux 6.10.14 внутри Docker Desktop: 38 целевых тестов и отдельная проверка отказа при запрещённых user namespaces прошли. Проверены CLI/RPC, SDK-инструменты, HTTPS, ACP, сетевые обходы, Unix socketpairs, защищённые файлы и интерактивный PTY. Повторный прогон macOS: 37 тестов прошли. Отчёт: `CORPORATE-IMPLEMENTATION.md` в корне репозитория.

Для вложенного тестирования в Docker нужны права на создание namespaces и нового `/proc`. Временный тестовый контейнер использовал `--cap-drop ALL --security-opt no-new-privileges --security-opt systempaths=unconfined --security-opt seccomp=unconfined`; Pi затем обязательно установил собственный seccomp-фильтр. Это настройки тестового окружения, а не рекомендация менять глобальную конфигурацию Docker или запускать корпоративный проект с открытой сетью без launcher.

Корпоративный сервер, его TLS/CA, фактическая авторизация и инфраструктурный прокси ещё не проверены: адрес и протокол не предоставлены. Сборка не установлена вместо обычного Pi. Полный исходный тестовый набор Pi не запускался; проверялись нужные для изменения сценарии. Binary/Bun, Windows и нативная Linux x86-64 машина не проверялись. `npm audit --omit=dev` для производственных зависимостей Pi и плагина на 2026-10-04 не сообщил известных уязвимостей; это не является полным аудитом стороннего кода или доказательством отсутствия утечек.
